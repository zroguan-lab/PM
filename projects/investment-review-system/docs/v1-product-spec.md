# 投资决策复盘系统 V1｜产品与开发规格

## 1. 产品原则

- 核心闭环：判断 → 证据 → 决策 → 结果 → 归因 → 学习。
- 新建判断以 1–3 分钟完成为约束，必填项只保留：日期、标的、资产类型、判断逻辑、支持证据、决策、信心度、验证周期。
- 原始判断采用追加式历史：保存后不覆盖原文，只能追加备注；若确需修正，新增一条修订记录并保留旧版本。
- V1 单机、单用户、离线优先，不接行情、券商、新闻或自动交易。

## 2. 信息架构与页面原型说明

### 全局导航

左侧导航：数据看板、新建判断、判断记录、待复盘。顶部只保留全局搜索与“新建判断”主按钮。

手机端收起为底部四项导航；表格切换为纵向记录卡片。

### 数据看板 `/`

- 第一行：总判断数、验证中、已复盘、判断正确率。
- 第二行：平均信心度、平均收益、平均超额收益。
- 主图区：信心度校准表，按 0–49、50–59、60–69、70–79、80–89、90–100 分桶，展示样本数、平均信心度、真实正确率与校准差。
- 下方：最近判断与即将到期记录，帮助用户继续闭环，而不是堆叠更多图表。

统计口径：正确率默认只统计 `正确` 与 `错误`，`部分正确`、`无法判断` 不进分母；页面提供口径说明。收益统计只纳入有实际收益的已复盘记录。

### 新建判断 `/judgments/new`

- 单页表单，不做向导。
- 第一屏顺序：标的 → 判断逻辑 → 支持证据 → 决策 → 信心度 → 验证周期。
- 日期默认今天；到期日根据周期实时计算；资产类型可记住最近选项。
- 参考价格、基准、标签放入“更多信息”，默认折叠。
- 主操作只有“保存判断”；支持 `Ctrl/⌘ + Enter` 保存。

### 判断记录 `/judgments`

- 搜索：标的、判断文字、证据、标签。
- 筛选：状态、资产类型、决策、信心区间、日期范围。
- 桌面端表格列：日期、标的、判断、决策、信心度、验证周期、状态、结果。
- 点击整行进入详情；详情按时间顺序展示原始判断、追加备注、复盘结果和修订历史。

### 待复盘 `/reviews`

- 默认按逾期天数倒序，突出最需要处理的记录。
- 点击“开始复盘”进入 `/judgments/[id]/review`。
- 复盘表单分三段但保持同页：结果、归因、学习。
- 实际收益、基准收益均由用户输入；超额收益自动计算为 `实际收益 - 基准收益`。
- 提交复盘后状态变为已复盘；复盘内容允许后续修订，但每次修订留痕。

## 3. 状态与关键规则

- `验证中`：尚未到期，且没有已提交复盘。
- `待复盘`：到期日不晚于本地今天，且没有已提交复盘。
- `已复盘`：存在当前有效复盘版本。
- 状态不建议持久化为数据库字段，查询时由到期日和复盘是否存在计算，避免日期跨天后状态失真。
- 自定义周期直接保存到期日；预设周期同时保存枚举值，便于统计。
- 判断正确性不要根据收益正负自动推断，必须由用户独立选择。

## 4. 推荐技术方案

- Next.js（App Router）+ TypeScript：页面与 Route Handlers 放在同一进程，Windows 一键启动更简单。
- SQLite + Drizzle ORM：模式显式、迁移轻量，后续 AI 分析可以直接读取结构化数据。
- Zod：表单与接口共用校验。
- 原生 CSS 或轻量组件层：V1 不引入重型设计系统。
- 本机启动：`start.bat` 执行依赖检查、迁移并启动 `next dev`；后续可增加生产版 `start-prod.bat`。
- 数据文件建议放在项目的 `data/investment-review.db`，并提供备份提示；数据库文件加入 `.gitignore`。

## 5. API 边界

- `POST /api/judgments`：创建判断。
- `GET /api/judgments`：分页、搜索、筛选。
- `GET /api/judgments/:id`：详情与完整时间线。
- `POST /api/judgments/:id/notes`：追加备注。
- `POST /api/judgments/:id/revisions`：创建修订版本。
- `POST /api/judgments/:id/reviews`：提交复盘。
- `POST /api/reviews/:id/revisions`：修订复盘并留痕。
- `GET /api/dashboard`：聚合指标与信心度校准。
- `GET /api/export?format=csv|json`：导出；CSV 推荐打包 judgments、notes、reviews 三个文件。

## 6. 开发任务拆分

### P0｜闭环可用

1. 工程骨架：Next.js、SQLite、Drizzle、迁移、中文深色布局、Windows 启动脚本。
2. 数据层：建表、种子数据、状态计算、日期与收益计算测试。
3. 新建判断：快速表单、校验、预设/自定义周期、保存成功反馈。
4. 判断记录：列表、搜索、核心筛选、详情时间线、追加备注。
5. 待复盘与复盘：到期查询、结果/归因/学习表单、超额收益计算、提交与留痕。
6. 看板：7 个基础指标、信心度分桶真实正确率、最近与即将到期记录。
7. 导出与运行：JSON/CSV 导出、备份说明、一键启动、README。

### P1｜上线前打磨

8. 响应式与可访问性：360px 手机适配、键盘操作、焦点与错误提示。
9. 数据安全：SQLite 事务、删除改为软删除或暂不提供删除、导出回归测试。
10. 验收：用 BTC 示例走完整闭环；跨日期状态变化；空数据和少样本统计；Windows 干净环境启动。

## 7. 建议实施节奏

- 里程碑 A：工程 + 数据层 + 新建判断。
- 里程碑 B：记录详情 + 待复盘 + 完整闭环。
- 里程碑 C：看板 + 导出 + 响应式 + Windows 验收。

每个里程碑都应有可运行版本。V1 完成标志不是页面数量，而是一条判断能从创建走到复盘，并永久保留原始判断与学习记录。

## 8. 验收用例

1. 创建 BTC 判断，信心度 70%，周期 30 天，参考价格可为空。
2. 保存后确认原始判断和证据不可原地覆盖；追加一条备注。
3. 将测试数据到期日设为今天，记录自动出现在待复盘。
4. 输入结束价格、实际收益和基准收益，系统自动得到超额收益。
5. 完成正确性、归因和三项学习内容，提交后状态显示已复盘。
6. 看板总数、状态、正确率、平均值与 70–79% 信心区间同步更新。
7. 导出 JSON 和 CSV，能恢复判断、备注、版本与复盘之间的关联。
